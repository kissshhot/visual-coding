# Visual Coding Agent 开发计划

当前进度：已完成离线闭环与真实多模态反馈闭环。已接入现有 Chat Completions 网关，支持参考图、已有页面修改、截图诊断、模型生成修复、重新评审和真实点击验证，并记录调用用量、版本与证据。已补齐 visual_compare 和 5 个固定任务的初稿/修订后对比，分别量化像素差异与独立交互结果。下一步将量化差异用于更严格的修订停止条件，扩展多视口和感知评分。

## 目标与范围

首版面向单页 Web：根据参考截图和文字要求生成页面，或修改已有页面，通过“编写代码 → 运行渲染 → 观察差异 → 修改 → 验证”完成交付。

## 核心职责

- **任务规划**：解析视觉目标、交互要求和已有代码，拆分可验证的修改步骤。
- **执行循环**：调用 Plugins 读取和修改代码、运行项目、观察页面，决定下一步操作。
- **反馈决策**：结合目标截图、渲染截图与运行错误判断问题，优先修复关键差异。
- **状态管理**：记录代码版本、工具调用和渲染产物，支持重试、回退与预算限制；代码修改后重新验证。
- **结果评估**：分别记录运行成功、视觉完成度和交互通过情况，保留初始与最终结果。

## 仓库与接口

建议模块：`agent/`（规划与循环）、`models/`（模型适配）、`evaluation/`（任务与评分）、`examples/`（示例）。首个入口使用 CLI。

通过 MCP 调用 `visual-coding-plugins`，遵循其版本化工具契约。Agent 负责规划、判断和停止条件，Plugins 负责执行工具及返回证据。

## 开发顺序

1. **跑通链路**：选定一个支持图像输入和工具调用的模型，完成截图输入、页面生成、启动与截图保存。
2. **形成闭环**：加入视觉反馈、局部修复、错误重试和最大轮次／耗时预算；支持已有页面编辑。
3. **建立评测**：固定 5 个小任务，覆盖布局重建、局部修改和简单交互；保存完整轨迹，比较初稿与修订后的结果。

## 首版验收

一条命令完成任务并输出源码、最终截图和运行记录；5 个任务均能结束并报告成功或失败；交付证据对应最终代码版本，运行、视觉和交互结果分别可查。

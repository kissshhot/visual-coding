# 固定评测任务 v1

5 个自建、受控的静态修复任务。每个目录包含文字任务、独立交互检查、固定参考源码和固定初稿源码。运行时渲染参考截图，模型只能收到参考图与候选源码，不能读取参考源码。

| 任务 | 覆盖能力 | 初稿缺陷 | 交互检查 |
| --- | --- | --- | --- |
| 01-dashboard | 双栏与卡片布局 | 侧栏过窄、指标卡片变成单列，操作区落到首屏之外 | 创建报告、再次点击计数递增；操作/状态可见 |
| 02-storefront | 局部样式与视觉层级 | 商品卡片颜色、圆角、图片区高度、价格字号和按钮颜色错误 | 加入购物袋、再次加入计数递增 |
| 03-editorial | 排版与内容完整性 | 标题过大、正文被截断、保存按钮无效果 | 收藏、再次取消收藏及状态变化 |
| 04-settings | 表单布局与输入状态 | 输入框拥挤、摘要错位、保存未使用输入值 | 输入 Ada 保存，再改为 Grace 保存，检查摘要和状态 |
| 05-pricing | 卡片对齐与状态切换 | 卡片间距、偏移、价格字号错误；切换只更新提示 | 月付→年付→月付，核对金额、周期和状态 |

## 固定协议

- 视口 1200×800、DPR 1、同一 Chromium；字体和页面素材均本地可用。
- 参考、初稿、修订后均使用独立 MCP 进程/浏览器上下文。记录浏览器版本。
- 分别采集 idle（初始）与 clicked（首次点击后）状态；参考和候选必须同状态比较。重复点击/第二个姓名另做检查，不混入 clicked 截图。
- 首屏状态文本和断言元素要求在视口内完整可见。因此仪表盘初稿的逻辑可执行，但首屏操作/状态不可见仍会失败；这不是把所有失败都解释成 JavaScript 故障。
- RGB 通道阈值 8。每个状态须变化像素比例 ≤ 1%，且 RGB MAE ≤ 2；两个状态均通过才算视觉达标。
- 表中平均差异是两个状态的等权均值，整体是 5 个任务的等权均值；不是感知质量分数。
- 交互结果独立于模型“通过”判断，最终源码冻结后重新启动浏览器验证。交互通过要求主操作和后续操作都满足断言。
- 每题最多 3 次修复、50 次 Agent 决策、10 分钟；模型配置默认最多 12 次请求，含重试。
- 每题运行一次，模型输出不满足结构化格式可有界重试；不按结果择优重跑。Agent 失败仍冻结当前源码评分并保留失败标记；基础设施导致无有效配对的任务记为无效，均值报告实际分母。
- 报告保存任务内容 SHA-256、运行器摘要、固定参数、模型请求/用量、代码版本、源图哈希、截图、差异图、逐项检查。

## 运行

在 Agent 仓库执行：

```sh
npm run build
npm run benchmark:validate  # 参考源码校准，不调用模型
npm run benchmark          # 真实模型修复 5 个初稿
```

模型使用本机已有 `.env` 配置。校准模式把参考源码复制为候选，其结果不能当作模型表现。两种模式输出目录和标题明确区分。

报告位于新的 `runs/calibration-*/` 或 `runs/benchmark-*/`：`report.html` 可查看参考/初稿/修订后截图及差异图；`report.json` 为完整机器可读结果，另有 `report.md` 和 `summary.csv`。输出目录不允许复用，原始记录保留。CLI 在任一任务未达标或失败时返回非零退出码。

这些任务用于工程回归和研究原型，五个自建静态页面、单次运行不足以代表真实网站上的总体能力。下一版任务或阈值变更应升级协议，不能改动本轮结果来让它通过。
